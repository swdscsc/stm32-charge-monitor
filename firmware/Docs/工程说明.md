# 固件工程说明（STM32CubeIDE 导入步骤）

## 目标硬件
- 主控：STM32F103C8T6（Blue Pill，72MHz）
- 传感器：INA219（I2C，0x40）、NTC 10kΩ B3950（ADC1_IN0 / PA0）
- 显示：0.96 寸 OLED SSD1306 128×64（I2C，0x78，与 INA219 共总线）
- 执行器：有源蜂鸣器（PA1，高电平响）、继电器模块（PA2，高电平吸合，控制低压负载回路）
- 物联网（可选）：ESP8266-01S（USART1 PA9/PA10，115200bps）

## CubeMX 配置清单（生成工程后，把本目录 Core/ 下的源码覆盖进去）
| 外设 | 配置 |
|------|------|
| SYS | Serial Wire 调试，SysTick 默认 |
| RCC | HSE = Crystal/Ceramic Resonator；PLL ×9 → SYSCLK 72MHz，APB1 36MHz |
| I2C1 | PB6/PB7，Fast Mode 400kHz，7bit 地址 |
| ADC1 | IN0（PA0），软件触发，采样时间 71.5 Cycles，独立模式 |
| USART1 | PA9/PA10，115200-8-N-1，异步 |
| GPIO | PA1/PA2/PA3 推挽输出（蜂鸣器/继电器/ESP8266使能） |

## 源码结构
```
Core/
├── Inc/
│   ├── main.h        引脚定义（阈值与数据结构统一移至 protect_cfg.h）
│   ├── protect_cfg.h 阈值、防抖次数、monitor_data_t 单一事实源（主机可测）
│   ├── ina219.h      INA219 寄存器定义
│   ├── ntc.h         NTC 测温参数
│   ├── ssd1306.h     OLED 接口（Update 返回 HAL 状态）
│   ├── protect.h     保护状态机（HAL 无关）
│   └── esp8266.h     物联网开关(ENABLE_ESP8266)
└── Src/
    ├── main.c        时钟/外设初始化 + 固定周期主循环 + OLED 界面 + IWDG 健康喂狗
    ├── ina219.c      标定寄存器计算、电压/电流/功率读取（依据 TI SBOS499E），含 OVF 拦截
    ├── ntc.c         ADC→电阻→B参数方程→温度，滑动窗口滤波
    ├── ssd1306.c     数据手册初始化序列、6x8 字库、帧缓冲整帧刷新、8x16 大字号
    ├── protect.c     纯 C 状态机：防抖/报警/切断/故障自动恢复/阈值闭锁+显式恢复
    ├── protect_hal.c 继电器与蜂鸣器的 HAL GPIO 钩子（把硬件访问隔离出状态机）
    └── esp8266.c     AT 指令连 WiFi/MQTT，JSON 遥测发布
```

## 关键参数
- INA219：分流电阻 0.1Ω / 2W，Cal = 4096，电流分辨率 0.8mA/bit；**VBUS 规格上限 26V**，寄存器编码跨度 32.76V 不是可承受电压
- 保护阈值：45℃ 报警、60℃ 切断、21V 过压（对应 20V 额定测试点、低于 26V 器件上限）、**2.5A 过流**（暂定软件值，须按分流器/模块额定值复核），连续 5 次超限才动作
- 看门狗：IWDG LSI/64、Reload=1250 ≈ 2s；仅在一个完整采样+保护周期跑完后喂狗；调试可用 `-DDISABLE_IWDG`
- 采集周期 100ms（INA219 128 次平均转换约 42ms，满足奈奎斯特与稳定性要求）

## 编译下载
1. STM32CubeIDE → File → Import → Existing Projects → 选择 firmware 目录
2. Project → Build Target（生成 .elf/.bin）
3. ST-Link 下载（SWD），或串口 ISP

## 验证方式（无硬件时）
见仓库 `simulation/` 目录：Python 对 INA219 标定换算、NTC 测温换算、保护状态机做了
数值仿真，输出论文第 6 章测试曲线（电压/电流/功率/温度 + 保护动作时序 + 误差分析）。
