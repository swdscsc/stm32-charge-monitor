## 仍需处理的重点问题

### P0 — 上电和实物测试前必须核验
1. **继电器触发电平未被硬件证实**：固件按 PA2 高电平吸合、低电平断开编写。部分继电器模块为低电平触发。必须先断开功率负载，实测 GPIO 与模块 IN 的有效电平；若模块低触发，当前 fail-safe 逻辑会反向。
2. **INA219 电压能力边界**：芯片 VBUS 规格上限为 26V。13 位寄存器的编码跨度不代表芯片可承受 32.76V。硬件输入必须限制在规格范围内。
3. **分流电阻热设计**：0.1Ω 在 2.5A 时耗散约 0.625W。建议至少 2W 额定并核验温升、焊盘、铜箔、端子与导线。电流保护阈值 2.5A 是暂定软件值，不是已经验证的安全额定值。
4. **功率回路缺少完整保护验证**：最终原理图需明确保险丝/限流源、反接保护、连接器和线材额定值、继电器触点 DC 额定值、分流器位置与极性。不得将本功能连接图当作投板原理图。
5. **禁止直接接市电或未经验证的手机/贵重设备**：先用隔离限流电源、电子负载和低压逐级验证；USB-PD 高电压档必须使用合规 PD 触发模块并确认输出。

### P1 — 影响功能完整性和可靠性
1. **CUTOFF 恢复入口缺失**：Protect_Recover() 有函数，但 main.c 没有按键/菜单/串口命令调用。当前实际表现为故障后闭锁，需重新上电才能恢复（且重启仍先断开）。应增加实体按键或经确认的本地恢复交互，并设置长按/二次确认。
2. **I²C 设备故障反馈不完整**：SSD1306_Update() 当前忽略 I²C 发送返回值，OLED 掉线不会被系统状态标记。建议为 OLED 增加在线状态与错误计数。
3. **INA219 功率寄存器未用于系统数据**：驱动读取了 power 寄存器，但主程序以 V × I 计算 g_mon.power。建议明确选择：保留 V×I 并删除多余寄存器读取，或做两种功率读数一致性比较。
4. **ESP8266 发送为同步调用**：启用后可能阻塞主循环，破坏 100ms 保护采样节拍。应改成 UART DMA/中断 + 状态机，或暂时保持禁用。
5. **无独立看门狗**：当前未发现 IWDG 初始化与喂狗流程。应在确认主循环关键任务健康后再喂狗，并验证复位时继电器硬件默认断开。
6. **C 代码缺少直接单元测试**：现有 Python 模型不能证明 protect.c 实际实现正确。建议把保护逻辑抽成纯 C 模块，用 Unity/CMock 或 host gcc 编译测试，覆盖故障、阈值、连续计数、恢复边界。
7. **继电器安全状态依赖外部电路**：仅靠 GPIO 初始化低电平不能保证 MCU 复位/未上电时继电器一定断开。硬件需设置确定的下拉/驱动默认态，并在实物验证。
