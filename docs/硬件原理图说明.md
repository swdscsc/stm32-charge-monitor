## 1 怎么读这张图

- **电源符号**：`3.3V`（蓝短棒，`—`）和 `5V`（红短棒）表示取电点，`┻` 为就近接地。**同名电源符号即等电位**，不再画横贯全图的长母线，避免电源线穿越元件框造成读图歧义。
- **青色标签（如 `PA9/TX`、`PA10`、`PA3`）是网络标号**：同名即等电位相连。ESP8266 离 MCU 较远，用标号代替跨整张图的长线，避免"蜘蛛网"。
- **本地接地符号 `┻`**：每个芯片/负载就近接地，不必都画回总地线。
- **元件符号**：`▭` 电阻、`‖` 电容、`◯(带箭头)` 三极管、`▷|` 二极管、`◯(带弧)` 蜂鸣器、极板+石英块为晶振。USB / LDO / MCU / INA219 / OLED / ESP-01 以功能框表示；NTC、蜂鸣器、继电器三块按**开架式电路**绘制，可直接对照接线。
- **引脚号以 `firmware/Core/Inc/main.h` 和 `main.c` 为准；元件值属于参考设计，最终须与实物模块和 BOM 核对。**

## 2 系统电源树（Rev.B：逻辑供电与被测回路分离）

```
① 逻辑供电（J1, USB Micro-B 5V）
   +5V  ──┬── AMS1117-3.3 ──► +3V3 ──► MCU / INA219(VS) / OLED / ESP8266 / NTC 上拉
          └── 继电器线圈 K1.A1（+5V）、D1 阴极

② 被测回路（J6, DC IN 5–20V，隔离低压直流）
   VIN_DC ──► R1(0.1Ω/2W) ──► SHUNT_N ──► K1.COM → K1.NO ──► J4 负载+
   J6.V- ──────────────────────────────────────────────► GND（与①共地）
```
- **两条回路必须分开**：MCU 供电不能被串进分流电阻，否则 AMS1117 会随被测电压变化而超压，且测到的只是逻辑电源电流。Rev.A 曾把两者混在同一 `+5V` 网络，Rev.B 已拆为 `+5V` 与 `VIN_DC`。
- 监控对象（快充头/电池组）的正端只进 INA219 的 `VBUS` / `VIN+`，负端经分流电阻后进 `VIN-`；**继电器只切断低压侧负载回路，不触碰市电**（安全边界见 `DESIGN.md §3.4`）。
- `VBUS` 接分流电阻**电源侧**（VIN_DC）而非负载侧：继电器断开后仍能读到真实输入电压，避免"断开→读到 0V→判安全→自动重合闸"的振荡。
- `J6.V-` 必须与 MCU 共地（INA219 的 VBUS 是对 GND 的单端测量）；只允许隔离低压直流，禁止市电与非隔离电源。
- 输入/输出各放 10µF 电解 + 0.1µF 陶瓷退耦；INA219、NTC 节点另有 0.1µF 滤波。

## 4 关键子电路设计要点

### 4.1 功率采集 INA219（右上）
- 原理图位号 **U2 = INA219**（SOT23-10，9 个有效引脚）、**U3 = AMS1117-3.3**；早期 BOM 曾把两者位号写反，已更正。
- 分流电阻 R1 **0.1Ω / 1% / 2W** 串在 `VIN_DC` 被测回路；`VIN+`/`VIN-` 跨其两端，**`VBUS` 接 `VIN_DC`（分流电阻电源侧）**。Rev.A 的符号漏画了 `VBUS` 引脚，总线电压寄存器实际无输入，Rev.B 已补齐。
- 标定：`Cal = 4096`、`I_LSB = 0.8mA/bit`、`Power_LSB = 16mW/bit`（见 `ina219.h`）；总线电压寄存器右移 3 位取 13 位、LSB=4mV；寄存器编码跨度约 32.76V，但 INA219 芯片规格的总线电压上限是 26V，不能按 32.76V 作为允许输入。
- 配置 128 样本平均、连续转换，整周期 ≈42ms，与固件 100ms 采集节拍匹配。

### 4.2 NTC 测温（左侧）
- 拓扑：`3.3V → 10k 上拉 → ADC 节点(PA0) → NTC(10k@25℃,B3950) → GND`。
- 换算：`R_ntc = 10k × D/(4095−D)`，再经 B 参数方程得 ℃（见 `ntc.c`）。
- 异常剔除：`D=0`（短路）/ `D=4095`（开路）丢弃；采样 71.5 周期 + 上电 ADC 自校准 + 滑动窗口 N=8。

### 4.3 本地显示 SSD1306（右中）
- 0.96" OLED，I2C 占 2 引脚；帧缓冲驱动，关键参数 8×16 大字号（见 `ssd1306.c`）。

### 4.4 报警 / 切断执行（左下、下中）
- 蜂鸣器、继电器均由 **NPN(S8050) 低边开关**驱动（GPIO 经 1k 基极电阻），不直接灌电流，保护 MCU 引脚。
- 继电器线圈并 **1N4148 续流二极管**，防止关断反峰击穿三极管。

### 4.5 物联网（右下，可选）
- ESP-01 经 `EN` 使能、`USART1` AT 指令接 MQTT，1s 周期 JSON 遥测；编译开关 `ENABLE_ESP8266` 整体裁剪（见 `esp8266.c`）。

### 4.6 时钟
- 8MHz 外部晶振（HSE）→ PLL×9 = 72MHz 系统时钟（见 `main.c` `SystemClock_Config`）。

## 5 与固件保护逻辑的对应

固件状态机（`protect.c`，阈值在 `main.h`）：

| 事件 | 固件动作 | 硬件表现 |
|------|---------|---------|
| 45℃ ≤ T < 60℃，连续 5 周期 | 进入 `ALARM` | 蜂鸣器响，保持供电 |
| T≥60℃ 或 V≥21V 或 I≥2.5A | 进入 `CUTOFF`（闭锁） | 继电器断开 + 蜂鸣器持续报警 |

> **21V 的取值依据**：`DESIGN.md §1` 的 FR-1 按 **20V / 2.5A 保守测试点**，`TESTS.md` 回归真值覆盖 5/9/12/15/20V，所以 21V = 20V 额定 + 1V 余量，且低于 INA219 的 **26V 器件上限**（`protect.c` 与 `ina219.c` 均按 26V 拦截）。它测的是 `J6` 被测输入，**不是 MCU 的 5V 供电轨**；请勿把阈值改为 6V，那会把 9–20V 的正常工况全判为过压。
| 达危险级后人工恢复 | `Protect_Recover()` | 继电器重新吸合 |

- **防抖**：电压/电流/温度超限连续 `ALARM_DEBOUNCE_COUNT=5` 次采样确认；关键传感器无效时立即切断，毛刺不误动。
- **滞回**：报警退出需温度回落到阈值下 3℃（`TEMP_ALARM_HYST`），避免蜂鸣器在阈值附近抖动。
- **传感器失效保护**：当前代码对 INA219 读取失败或 NTC 无效值立即置故障标志并进入 CUTOFF；此逻辑仍需在断开负载的台架上验证。

## 8 烧录与实测注意事项

1. 用 ST-Link（SWD：`PA13/SWCLK`、`PA14/SWDIO`、`NRST`）烧录；首次上电确认 3.3V 轨无短路再通电。
2. I2C 总线上 OLED(0x78) 与 INA219(0x40) 地址不冲突；若 OLED 模块自带 4.7k 上拉，可省略板载上拉避免过强。
3. 继电器线圈务必并联续流二极管；切断对象仅限低压侧。
4. `ENABLE_ESP8266` 默认裁剪；启用前需核对 `esp8266.c` 的接口实现与串口配置，当前不宣称已完成非阻塞发送。
5. 分流电阻建议≥2W，并根据实际散热/降额复核；2.5A 时理论功耗 `I²R = 0.625W`，注意散热与 1% 容差对电流精度的影响（实测两点校准可进一步压缩）。

> **关键优势**：与 DXF 导入不同，`.SchDoc` 保留了完整的**电气连接关系（网表）**、**元件参数**、**位号/值注解**，无需重新连线。**坐标单位为 1 单位 = 0.254 mm (10 mil)**，与底图 1:1 毫米对位精确。
> 另：生成器已在本地 Altium 17.0 实测 **Compile 0 error**（Rev.B）。Rev.B 的 Messages 面板曾有约 97 条 `Floating Net Label` / `Floating Power Object GND` 警告；此前误判为"逐引脚 stub 画法的 ERC 判定差异"，现已定位为**引脚电气热点坐标错误**并修复。**根因与修复（Rev.C）**：Altium 的 `RECORD=2` 引脚记录中 `LOCATION` 是「引脚根部」(贴元件体一侧)，电气热点 = `LOCATION + 方向 × PINLENGTH`；方向由 `PINCONGLOMERATE` 低 2 位编码。从本机 Altium 17.0 原生 Examples 的 446 个引脚逐点反推：导线端点落在 `LOCATION±PINLENGTH` 的有 390 个、落在 `LOCATION` 的仅 5 个；方向位 `0/1/2/3 → +X/+Y/-X/-Y`。生成器早期把 `LOCATION` 直接写成热点、且四个方向位全部用反，导线因此落在非电气点上，末端 97 个网络标号/电源端口被批量判为 Floating。`simulation/altium_schdoc.py` 的 `component()` 已改为写根部坐标 + 正确方向位，并用整数坐标单位反推（规避 `mm()` floor 与 `mm2u()` round 差 1 单位）。TC09 已升级为复算电气热点：**99 个引脚热点与 97 个标号/端口全部精确落在导线端点上**。
> TC09 现已支持两种连接画法（本项目的 stub 短导线式、以及多图纸工程常用的「标号直贴引脚热点」direct 式），并兼容 Protel ASCII 与 OLE 复合文档；内置 5 组内存回归样本，可用 `--path FILE|DIR` 校验任意原理图。用另一套生成器产出的 7 图纸工程做过独立交叉验证：201 引脚 / 155 标号端口中 153 个对齐，`direct` 画法本身完全合法——再次印证问题只在引脚坐标，不在画法。
> **诚实性边界**：修复后尚未在 Altium GUI 复编译（当时该 Altium 实例被另一工程的 8 个未保存文档占用，未抢占），因此**不能宣称 0 Warning**；请在空闲实例中按上述步骤复编译并读 Messages 面板。ERC 仍未执行，答辩前应逐条复核。
